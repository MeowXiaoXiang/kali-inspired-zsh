# 疑難排解

[回首頁](../README.md) · [操作手冊](usage.md) · [設定手冊](configuration.md)

## 設定改了沒有生效

先確認目前使用 Zsh，例如執行 `print -r -- $ZSH_VERSION`，再檢查實際載入的設定檔。專案的 .zshrc 不會自動同步到 ~/.zshrc；修改後要按自己的安裝方式重新套用。

語法檢查：

```sh
zsh -n ~/.zshrc
# 有建立這個檔案時再檢查
zsh -n ~/.zsh_config
```

初始化選項放 ~/.zsh_config。修改插件開關或載入順序後，重新開啟 Zsh 比在原行程重複載入更容易確認結果。

若有使用 ZDOTDIR，Zsh 可能從該目錄讀取啟動檔；目前 README 的安裝步驟使用家目錄，請依自己的部署方式調整。

本設定的 `.zsh_config`、`.zsh_aliases`、`.zsh_local` 仍固定從家目錄載入，不會跟著 ZDOTDIR 改變位置。

## 自動建議或語法高亮沒出現

確認 .zsh_config 的對應開關為 "Y"，且檔案位於：

```text
~/.zsh/plugins/zsh-autosuggestions/zsh-autosuggestions.zsh
~/.zsh/plugins/zsh-syntax-highlighting/zsh-syntax-highlighting.zsh
```

發行版套件安裝到其他位置時，不一定會被目前的固定路徑自動找到。請使用 README 的目錄配置，或自行管理載入方式，避免重複載入。

自動建議需要有可用的歷史或補全結果；空白的新環境不一定會立即出現建議。預設建議顏色偏暗，也要留意終端機背景。

## 按鍵行為不同

檢查目前綁定：

```zsh
bindkey '^R'
bindkey '^[[A'
```

本設定預設採 Emacs 按鍵配置。~/.zsh_local、其他工具或終端機本身都可能影響按鍵；先確認是否有個人覆寫。Ctrl+方向鍵也取決於終端機送出的序列。

## Git 顯示慢半拍或狀態未知

- 工作區狀態預設快取 3 秒，可等候或執行下一個指令更新提示符。
- ~ 表示查詢逾時；! 表示查詢失敗，不能當成工作區乾淨。
- 大型儲存庫可適度提高 GIT_STATUS_TIMEOUT，但可能增加等待。
- 超前／落後是相對本機已知的追蹤分支；要更新遠端資訊需自行執行 `git fetch`。

可在該目錄直接執行 `git status` 檢查原生錯誤。其他 Git 查詢沒有共同的逾時限制。

## 路徑換行或符號顯示不正常

路徑縮短會保留完整目錄名稱。若名稱、時間或 Git 資訊太長，仍可能換行；實際所在的目錄不受影響。

先加寬終端機視窗，或在 .zsh_config 調整不需要的資訊。㉿ 等符號顯示異常時，可改回 `PROMPT_HOST_SYMBOL="@"`，並檢查字型與 UTF-8 環境。

## 負載數值不是 CPU 百分比

`load:數值` 反映 Linux 系統負載，並非 CPU 使用百分比。預設超過核心數 × 0.7 才出現；不需要時設定 `ENABLE_SYSTEM_LOAD="N"`。

## 解壓失敗或有部分檔案

確認原始檔存在、格式受支援、解壓工具已安裝，且目前目錄可寫入。缺少工具時會顯示對應套件提示。

遇到同名檔案時不覆寫；tar 可能已解壓其他不衝突的檔案後才回傳失敗。要重新操作可自行換到新建的空目錄，不要把失敗回傳視為「完全沒有寫入任何檔案」。

## 套件維護無法執行

`pkgup`、`pkgclean` 只支援使用 APT／DNF 的發行版，可能需要 sudo 密碼、可用軟體來源與網路。不支援的系統會回報錯誤，不會猜測使用其他套件管理器。

目前只在 Ubuntu 與 Fedora 測過這兩個函式；能辨識其他發行版家族，不代表已在那些環境完成驗證。

先查看套件管理器顯示的錯誤訊息。前一步失敗後不會繼續下一步，請先解決軟體來源、權限或套件相依問題。

## 還原設定與切回 Bash

使用安裝時產生的實際備份檔名：

```sh
cp -- ~/.zshrc.bak.YYYYMMDDHHMMSS ~/.zshrc
```

YYYYMMDDHHMMSS 代表備份時間，請替換成實際的時間戳記。若原本使用符號連結，另依原有管理方式還原連結。

要暫時略過個人設定，可執行 `zsh -f`；它仍可能讀取系統層級的設定。要更改登入 Shell 則使用：

```sh
chsh -s "$(command -v bash)"
```

這不會刪除 Zsh、插件或個人設定檔。
